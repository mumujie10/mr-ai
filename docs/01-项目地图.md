# 项目地图

一句话：**一个 Tauri 桌面壳，把多个命令行 AI 编程工具接进同一个图形界面**，附带一套插件体系和一个自带的运行时。

---

## 四份产物

| 位置 | 是什么 | 怎么产出 |
|---|---|---|
| `src/` | React 18 + TypeScript 前端 | `pnpm build`（`tsc --noEmit` + `vite build`）→ `dist/` |
| `src-tauri/` | Rust 后端：进程管理、协议适配、存储、原生能力 | `pnpm dev` 起调试；`pnpm exec tauri build` 出安装包 |
| `cli/` | 内置运行时（自带的那套 CLI，独立 pnpm workspace） | `pnpm cli:build` + `pnpm runtime:stage` → 落进 `src-tauri/resources/runtime/` |
| `packages/plugin-sdk`、`packages/plugin-ui` | 插件的公共契约与共享组件库 | 插件作者只依赖这两个包，见插件开发指南 |

**`cli/` 是独立项目**：它有自己的 `AGENTS.md`、`CONTRIBUTING.md`、`README.md`、`docs/`、测试配置与许可声明文件。那些是它的上游口径，**不要按本仓的中文文档规范去改写它**——里面的署名与许可文件有分发义务，改动需要单独决定。本仓文档只覆盖 GUI。

## 前端（`src/`）

```
src/
  main.tsx / bootstrap.tsx    入口与启动序列（主题、字体、语言在首帧前应用）
  App.tsx                     路由与外壳
  features/<模块>/            业务功能，一个目录一个领域
  components/
    base/                     基础控件：buttons、input、select、switch、tabs、tooltip…
    application/              跨功能的应用级组件：ai-chat、settings、agent-*、theme
    foundations/              图标等更底层的展示件
  lib/                        ipc.ts（后端调用面）、events、transport、storage、zoom…
  hooks/ utils/ types/        通用 hook、工具（含 cx.ts，见规范）、类型
  i18n/zh.ts en.ts            全部用户可见文案
  styles/                     typography.css（文本样式 token）、theme.css、globals.css
  version/                    app-version.ts + changelog.ts（应用内"版本更新"弹窗的唯一数据源）
```

`src/features` 现有 19 个模块：`bots` `browser` `chat` `commands` `files` `git` `launch-script` `mcp` `mission` `open-app` `pet` `plugins` `prompts` `settings` `shortcuts` `skills` `terminal` `update` `worktree`。

**归属原则**：功能行为放在实际负责它的 `features/<模块>` 里，通用 UI 才进 `components/`；引擎协议差异留在 Rust 适配层，**不要在 UI 里散布 `engine === "xxx"` 的特判**（唯一的例外是集中定义的常量入口，见 [02-架构与数据流](./02-架构与数据流.md)）。

聊天状态集中在 `src/features/chat/store.ts` + `store/` 子目录（`sessions` `messaging` `tabs` `preferences` `persistence` `engine-events` 等切片），组件通过选择器订阅，不在组件里私存会话状态。

## Rust 后端（`src-tauri/src`）

| 分组 | 文件/目录 | 职责 |
|---|---|---|
| 引擎接入 | `engine/`（`mod.rs` `registry.rs` `resolve.rs` `events.rs` `reader.rs` `job.rs` `bundled.rs` + 每个引擎一个适配器：`claude.rs` `codex*.rs` `kimi*.rs` `grok*.rs` `pi_family*.rs` `omp_acp.rs` `dsh*.rs` `agy.rs` `opencode*.rs` `qoder*.rs` `mcode*.rs`）+ `engine/models/` `provider_models.rs` `provider_files.rs` `channel.rs` `mr_providers.rs` `slash_commands.rs` | 启动子进程、协议差异、事件流、模型目录、渠道与供应商文件 |
| 会话与历史 | `history/`（`discovery` `reader` `scanner` `extract` `search` `*_titles`）、`db.rs` | 找到各 CLI 自己写的会话、扫描入库、搜索、自动标题 |
| 设置与状态 | `settings.rs`、`config.rs`、`paths.rs`、`proxy.rs`、`metrics.rs` | 应用设置读写（camelCase 落 JSON）、数据目录、代理 |
| 能力扩展 | `plugins/`、`plugin_host.rs`、`plugin_caps.rs`、`creator_skill.rs`、`skills_hub/`、`mcp/`、`memory/`、`bots.rs`、`prompts.rs` | 插件加载与权限、技能、MCP、长期记忆、智能体 |
| 远程访问 | `web.rs`、`web/dispatch.rs`、`relay.rs` | 局域网 HTTP/WS 桥、命令分发、外网中转 |
| 原生集成 | `git.rs` `git_worktree.rs` `terminal.rs` `files.rs` `fonts.rs` `clipboard.rs` `computer_use*.rs` `cu_overlay.rs` `pet_overlay.rs` `pets.rs` `browser.rs` `open_app.rs` `usage.rs` `updater.rs` `quit_guard.rs` `cli_lifecycle.rs` `dsh_host.rs` `agent_catalog.rs` | 各自的系统能力 |
| 装配 | `lib.rs`（命令注册、启动钩子）、`main.rs`、`event_sink.rs` | 把上面接起来 |

**加一个前端能调用的命令必须动三处**：`#[tauri::command]` 函数 → `lib.rs` 的 `invoke_handler` → `web/dispatch.rs` 的分发臂。第三处漏了，桌面端一切正常，**只有手机浏览器连进来时报"未知命令"**，这类缺陷最容易漏。
