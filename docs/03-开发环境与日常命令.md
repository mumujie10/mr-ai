# 开发环境与日常命令

## 工具链

| 需要 | 版本从哪来 | 说明 |
|---|---|---|
| Node | 20+ 起步，团队当前用 24 系列 | 没有 `engines` 字段约束，以能跑通 `pnpm build` 为准 |
| pnpm | **`package.json` 的 `packageManager: pnpm@10.29.3`** 是唯一权威 | 见下面的坑：corepack 在部分机器上会挂死 |
| Rust | stable，最低 `rust-version = 1.77.2`（`src-tauri/Cargo.toml`） | Tauri 2 需要较新的稳定版 |
| 系统 | macOS 需要 Xcode 命令行工具；Linux 需要 webkit2gtk 等 Tauri 依赖 | Windows 走 CI 构建 |

装 pnpm：

```bash
npm install -g pnpm@10.29.3     # 推荐
corepack enable && corepack prepare pnpm@10.29.3 --activate   # 理论上一行，但见坑
```

## 日常命令

```bash
pnpm install:all            # 前端 + cli/ 都装依赖（新 clone 后第一步）
pnpm dev                    # Tauri 桌面应用：vite dev（1420 端口）+ Rust 自动编译
pnpm build                  # tsc --noEmit + vite build —— 类型检查就在这条里
pnpm test                   # vitest run（jsdom，setup 见 src/test-setup.ts）
pnpm preview                # 构建产物预览
pnpm plugin-skill:docs      # 改了插件 SDK/扩展点后必须重生成 skill 文档
```

内置运行时与 `cli/`：

```bash
pnpm cli:build              # 构建内置 CLI
pnpm cli:verify             # 跑 cli/ 自己的校验门禁
pnpm runtime:stage          # 把构建产物搬进 src-tauri/resources/runtime/
pnpm runtime:build          # = cli:build + runtime:stage
```

发版打包：

```bash
pnpm build:mac                 # 签名 + 公证 + staple
pnpm build:mac:skip-notarize   # 只要签名包，跳过公证（本地自测）
```

Rust 侧（都在 `src-tauri/` 下执行）：

```bash
cargo check --quiet                     # 快速类型检查
cargo test --quiet --lib                # Rust 单测（当前约一千例）
cargo test --quiet --lib -- relay:: settings::   # 按模块过滤：多个过滤词必须放在 -- 之后
cargo test --quiet --test send_path     # 真实发送与中断链路
cargo test --tests --no-run             # 只编译全部集成测试目标（不运行）
```

`cli/` 侧（在 `cli/` 下，或 `pnpm --dir cli <脚本名>`）：`build`、`verify`、`typecheck`、`test:smoke`、`test:policy`、`test:byok`、`test:sandbox`、`test:status-contract`、`check:standalone`。

## 静态检查的实情

**本仓没有 ESLint、没有 Prettier、没有 `.editorconfig`**，也没有格式化门禁。风格靠三件事维持：

1. `pnpm build` 的 TypeScript `strict` 类型检查（`tsconfig.json`）
2. 评审时对照现有代码风格
3. 少数有测试看守的约定（例如 `src/utils/cx.ts` 必须与 `src/styles/typography.css` 的 `text-*` token 一一对应）

所以别在 PR 里顺手引入 lint 配置或全仓格式化——那会让每个文件的 diff 都变脏，属于需要单独决定的事。

## 会踩的坑（按出现过频率排）

| 坑 | 现象 | 怎么办 |
|---|---|---|
| **corepack 挂死** | `corepack ...` 超过 60s 无输出（在等 registry） | 直接 `npm i -g pnpm@<版本>`，别走 corepack |
| **`pnpm dev` 不一定重编译你改的 Rust** | 界面行为没变，以为改动没生效 | 退出应用 → `pkill` 掉残留进程 → 重跑 `pnpm dev`；核对进程启动时间与二进制 mtime |
| **同时开两份应用** | 端口/会话状态互相打架 | 启动前确认只有一份本项目的进程与 1420 端口 |
| **过滤 Rust 测试语法** | `cargo test --lib a:: b::` 报 `unexpected argument` | 写成 `cargo test --lib -- a:: b::` |
| **递归 grep 整仓超时** | `grep -r ... src docs` 卡死 120s（`cli/`、`target/`、`dist/` 太大） | 用编辑器的搜索或限定目录 |
| **zsh 空 glob 中断命令链** | `rm -f dist/*.zip` 无匹配时报 `no matches found`，后面的 `&&` 全不执行 | 写具体文件名，或 `setopt nullglob` |
| **zsh 把 `$VAR:path` 当修饰符** | `git show $SHA:src/x.ts` 打印出 commit 正文而不是文件 | 写 `"${SHA}:src/x.ts"` |
| **BSD 工具差异** | `grep -P` 静默无输出、`cat -A` 报 illegal option、没有 `timeout` | 换等价写法或写脚本 |
| **剪贴板丢中文** | `LANG`/`LC_CTYPE` 为空时 `pbcopy` 写中文静默失败 | `LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8 pbcopy < 文件` |
| **首次 cargo 拉索引看着像卡住** | `~/.cargo/registry` 空、没输出 | 是正常下载阶段，`pgrep -fl cargo` 确认还在跑；必要时注入系统代理 |
| **GitHub HTTPS 抖动** | `git ls-remote`/`fetch` 报 HTTP2 framing 错误 | 用 SSH |

## 真机能做到什么

- 界面上能做到的：手动点开设置、发消息、切引擎、看流式与状态。
- **自动化操作 GUI 做不到**：向系统发送按键/点击需要辅助功能权限，本机通常没有，所以"点击级验证"必须**由人在真界面上过一遍**，不能声称自动验证过。相关边界见 [04-测试与验收分层](./04-测试与验收分层.md)。
