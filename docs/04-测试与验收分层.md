# 测试与验收分层

本项目的交付口径不是"测试绿了"，而是**"哪一层验过、哪一层没验、为什么"**。这份文档定义各层能撑住什么结论。

---

## 六个层次

| 层 | 命令 | 能证明 | 不能证明 |
|---|---|---|---|
| **类型与构建** | `pnpm build`（`tsc --noEmit` + `vite build`） | 类型契约成立、前端能构建产物 | 行为对不对；运行时是否崩溃 |
| **前端单测** | `pnpm test` / `pnpm exec vitest run <路径>` | 组件逻辑、状态机、事件处理、渲染结果（jsdom 环境） | 真实浏览器布局、动效帧、原生窗口行为 |
| **协议与调度回归** | `node --experimental-strip-types --test tests/*.test.ts` | 流式调度、Markdown 解析、请求载荷这类不依赖 DOM 的核心逻辑 | 界面呈现 |
| **Rust 单测** | `cd src-tauri && cargo test --lib` | 命令注册、解析、存储与状态机的纯逻辑分支 | 真实子进程与外部 CLI 的行为 |
| **Rust 集成** | `cargo test --test send_path`（另有 `ask_live` `codex_probe` `plan_review` `terminal`） | 用假 CLI 进程走真实发送/中断/审批链路 | 真机上的原生输入法与窗口交互 |
| **浏览器夹具** | dev 服务下打开 `http://localhost:1420/tests/browser/<夹具>.html`（共 39 个） | 真实 React 提交、定时器交错、动效契约、深浅色与减少动态 | 打包后的原生应用 |
| **真机点击级** | `pnpm dev` 起应用或装包后人手点 | 用户实际看到的行为、系统权限、输入法、原生窗口 | ——只有这层能证明"用户体验对了" |

## 当前基线（会漂移，自己跑一遍数）

- 前端：**两百多个测试文件、约一千八百多例**，健康状态是全绿
- 有一个文件默认跳过：`src/features/plugins/runtime/git-tasks-smoke.test.tsx`——它需要 sibling 目录里那份外部插件仓库（`../ccgui-plugin/git-tasks/main.js`），缺了就跳过，**这是设计如此，不是失败**
- Rust 单测：**约一千例**，8 个 `#[ignore]`
- `cargo test --tests`（含集成测试）必须能编译；历史上这里出现过 `AppState` 字面量重复字段导致整串编译不过，所以改完 Rust 记得带上 `cargo test --tests --no-run`

**已知受机器负载影响的用例**：`engine::resolve::tests::npm_probe_times_out_and_reaps_child` 会真的 spawn 子进程，与 `pnpm build` 并发跑时可能超时变红，**单独跑就绿**。碰到先怀疑环境，别改断言。

---

## 缺陷修复的验证顺序

1. **先写能揭示旧行为错误的用例**：让它红，证明这个用例真的在测缺陷。
2. 改代码，让它绿。
3. 用临时探针反证有效性（把旧逻辑装回去看是否变红，或把新逻辑摘掉看是否变红），**验证完撤掉探针**。
4. 全量跑一遍受影响的链路，确认没有把别的行为带歪。

不许通过放宽断言、跳过测试、改验收标准来制造通过。

## 报告口径（写交付说明时照这个来）

必须分三档说清：

- **真机实测**：在应用里手动操作过，看到了预期结果
- **自动化覆盖**：哪条命令、哪个文件、多少例，实际结果（通过/失败/跳过各多少）
- **未能验证**：具体是什么、为什么给不了（例如"Windows 的 `CF_HDROP` 分支没做交叉编译，只核对过源码"、"输入法行为需要真实 macOS 输入法，本机缺辅助功能权限点不进界面"）

三条禁令：

- 不拿**退出码 0** 当"用户问题已解决"的证据
- 不把**局部基准/回放**的结果说成真实原生应用的提升；性能结论要写明测量对象与条件，区分"上游到达间隔 / IPC 等待 / 解析成本 / 页面显示延迟"
- 不把**热更新**说成已重启；区分前端热更新、Rust 自动重编译、完整重启

## 界面与交互类改动

- 用户可见的交互反馈、基础组件视觉、动效时长，以 [ui-ux-spec.zh-CN.md](./ui-ux-spec.zh-CN.md) 为准，并在**同一个改动里**更新它；新增刷新/重载入口要登记进它的清单
- jsdom 量不到的东西：真实布局、过渡时长、`matchMedia` 断点。桌面视口相关的验证用浏览器夹具，并在夹具里按需打桩 `matchMedia`
- 改了 SDK / 扩展点 / 权限目录 → `pnpm plugin-skill:docs`，否则 `creator-skill-docs.test.ts` 会红

## 并行工作

本仓允许同时开多个会话/成员改同一目录。动手前 `git status --short` 看清哪些文件是别人未提交的内容；批量改写（例如统一改文案）时**跳过脏文件**，别覆盖别人未完成的工作。提交与推送规则见 [团队规范/分支提交与评审](./团队规范/分支提交与评审.md)。
