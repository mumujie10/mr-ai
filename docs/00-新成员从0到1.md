# 新成员从 0 到 1

目标：三天内从 clone 到合入第一个改动，并且知道**自己说的"验证过了"能撑到什么程度**。

---

## 第 1 天：把它跑起来

```bash
git clone <仓库地址> && cd mr-ai
pnpm install:all      # 前端 + 内置 CLI（cli/）都装
pnpm dev              # 启动 Tauri 桌面应用（前端热更新 + Rust 自动重编译）
```

看到应用窗口、能选引擎发一条消息，第 1 步就算过了。

需要知道的三件事：

1. **它是 Tauri 2 应用**：React 18 + TypeScript 前端（`src/`），Rust 后端（`src-tauri/`），二者通过 Tauri 命令与事件通信。`pnpm dev` 起的是完整桌面应用，不是纯浏览器页面。
2. **引擎是外部 CLI**：应用自己不实现模型调用，而是接管你机器上装好的命令行 AI 工具（Claude Code、Codex CLI、Kimi CLI、Grok CLI、Pi、OMP、DeepSeek Harness、Antigravity、OpenCode、Qoder、MiniMax Code），外加一个**随应用打包的 MireAI 内置运行时**（默认引擎）。没装某个 CLI，那个引擎在设置里就显示未安装——这是正常状态，不是 bug。
3. **只有 BYOK**：产品不带云端账号体系，模型渠道全部由你为对应 CLI 配置的 API key 决定。第一次跑要至少配一个能用的渠道，否则发消息只会看到错误。

## 第 2 天：知道东西在哪

按顺序读，别跳：

- [01-项目地图](./01-项目地图.md) — 目录归属、模块清单、哪些目录是"你的改动应该落在这里"
- [02-架构与数据流](./02-架构与数据流.md) — 一次"发消息 → 流式回复"在代码里走的路径，以及为什么新增一个后端命令要改三个地方
- [03-开发环境与日常命令](./03-开发环境与日常命令.md) — 命令面与本机坑
- [04-测试与验收分层](./04-测试与验收分层.md) — **必读**。本项目的交付口径是"说清哪层验过、哪层没验"，不是"测试绿了"

然后跑一遍全量验证，确认你手上的仓库是干净的：

```bash
pnpm build                        # 类型检查 + 前端构建
pnpm test                         # 前端单测（vitest，jsdom）
cd src-tauri && cargo test --lib  # Rust 单测
```

三个都得过。跑不过别硬着头皮改，先问：可能是你环境缺东西，也可能是仓库本身的问题——**这两种情况在报告里必须写清楚是哪种**。

## 第 3 天：第一个改动

### 挑任务

优先挑能沿着一条完整链路验证的小改动。好入口：

- 设置页某行的文案或交互（`src/features/settings/`）——改完能在界面上看到，测试有现成夹具
- 引擎适配层的协议差异（`src-tauri/src/engine/`）——有 `cargo test --test send_path` 这类真实发送链路测试
- 界面反馈缺陷（`docs/ui-ux-spec.zh-CN.md` 里每条规则都指向具体文件和回归测试）

### 动手前

- **先确认这个目录有没有别人在改**：`git status --short` 看一眼。本仓允许并行会话，批量改写时跳过脏文件，别覆盖未提交内容。
- **先看这条链路的测试**：找同名 `*.test.tsx` / `*.test.ts`，跑一遍，知道基线是什么样。
- **缺陷优先构造能揭示旧行为错误的用例**，再改代码。改完把用例失效的临时手段撤掉。

### 交付口径

一句实话：**退出码为 0 不等于用户问题解决了**。交付说明要写清：

- 改了什么、为什么这样改（行为变化，不是文件清单）
- 哪层验证过：单测 / 类型检查 / 构建 / 真机点击
- 哪层没验证，以及为什么（例如"Windows 分支未交叉编译"、"真机点击级需人工，本机缺辅助功能权限"）

### 提交与推送

- **不要自己提交**。本仓的硬规则是：任何 `git commit` / `git push` 都必须由人明确指示，历史授权不顺延。
- 分支流程、PR 要求、评审规则见 [团队规范/分支提交与评审](./团队规范/分支提交与评审.md)。本仓是 `main` 上开发、按 tag 发版。

## 读完应该能回答

- 新增一个前端能调用的 Rust 命令，要改哪三个地方？为什么第三处漏了会只在手机端出问题？
- 应用的设置项存在哪里？为什么 `Option<bool>` 这种三态字段前后端都不能当成普通 bool？
- 内置运行时的数据目录是什么？哪个环境变量能覆盖它？
- 我改了输入框的回车行为，除了单测还需要做什么验证？要更新哪份文档？
- 为什么 `pnpm test` 全绿不能直接写成"功能已验证"？

答不上来就回到对应那篇。
