# 安全与隐私红线

这里列的是**不可协商项**。与便利、进度、"上游就是这么做的"冲突时，以本文为准；需要破例必须由维护者显式决定，并在代码旁写下原因。

---

## 凭据

- **API key 只通过子进程环境变量传**给对应的 CLI（例如 `MCODE_PROVIDER_API_KEY` 这类）。
  禁止进入：命令行参数（`argv` 会被进程列表和 shell 历史看到）、日志、错误信息、截图说明、测试夹具、提交记录。
- **渠道密钥在本机是明文落盘的**（GUI 的应用配置与内置运行时的 `config` 各一份）。因此：
  - 任何调试输出、崩溃上下文、遥测类上报都不许带上这些文件内容或其字段值。
  - 不要把用户真实配置文件路径 + 内容一起写进文档或 issue。
  - 界面上展示密钥的位置默认掩码，复制/导出这类操作要有明确动作。
- **不读 macOS 钥匙串**，不以任何方式把系统凭库当成本应用的存储。
- 不写死与机器相关的值：端口、绝对路径、真实账号 / 租户 ID 不进代码、示例与测试。

## 日志与上报

- 日志保留**错误上下文**（哪个环节、什么条件、什么状态），**不输出**凭据、完整用户对话、以及其他敏感数据。
- 临时调试输出在合入前清掉。
- **本项目已经主动拔掉的外发能力，不许复活**：MiniMax 业务埋点与 telemetry 命令面、每日签到云客户端、反馈内容上传、自动错误诊断上传、云端权限分类器、CLI 侧的远端 Skill Hub。它们不是"暂时禁用"，是删掉的功能。
- **任何新增网络外发都要显式评审**：外发什么数据、发到哪、谁触发、能否关闭、失败怎样。默认答案是"不外发"。产品是 BYOK 定位，发送给模型的内容遵循用户为对应 CLI 配置的渠道边界——不要越过它替用户联系任何第三方。

## 系统权限与本机数据

- **权限按次授予，不做全局开关**。电脑操控（computer use）只在一次任务回合内挂载；急停快捷键也只在那期间武装，平时不抢 Esc。
- 权限状态要**读真实系统状态**展示已授权/未授权，不靠猜、不把未授权说成已就绪。缺权限时文案要讲清缺什么、去哪里开。
- **剪贴板**：只在用户粘贴文件这种明确动作时才向系统剪贴板探测文件 URL（`clipboard_file_paths`），读到什么用什么，不落盘、不上报。测试使用私有 pasteboard，**不读写用户真实剪贴板**。富文本粘贴只取 `text/plain`，不让 HTML 里的样式与标记泄漏进输入框。
- 长期记忆、会话历史、设置都只在本机。新增"跨项目/跨设备记住东西"的能力属于新的隐私边界，需要单独决定与说明。

## 远程访问

- 局域网桥是 token 认证的 WebSocket；配对密钥会轮换，桌面端持有权威。手机端能调用的命令必须**显式**在 `web/dispatch.rs` 加分发臂——不加分发臂的命令对手机不可见，这是特性不是遗漏。
- 拿不到本机能力的（例如 OS 剪贴板文件路径）在该层**明确回空**，前端按"没有文件"处理，不假装成功。
- **中转（relay）的开关是会话态**：默认每次启动要人手动连。只有"无人值守"这一个标记持久，它是用户明确授权"重启后也要能被远程触达"。改这条语义要当成权限变更来评审，不是普通重构。

## 插件

- 插件的能力来自 manifest 声明的权限；宿主侧审查（install-time）与隔离是安全边界，**不静默提权**、不给插件绕过审查的通道。
- 样式与资源走既有审查通道（`@layer ccgui-plugins`），不为了省事让插件直接注入未审查的标记。
- 改 SDK / 扩展点 / 权限目录 = 改对外契约：同一个改动里重生成插件开发 skill 文档，并说明兼容性影响。

## 供应链

- **不随意新增依赖。** 需要新增时，PR 里写清：为什么现有手段做不到、体积与编译时长影响、维护状态、许可证。
  参考做法：加之前先查 `Cargo.lock` / `pnpm-lock.yaml`——本项目加剪贴板能力时，`objc2` 三个包已经由 `xcap`/`enigo` 传递引入，声明为直接依赖**没有新增任何 crate**，这才叫增量可控。
- **发布身份三件事由维护者决定，AI 与新成员不得自行修改**：代码签名身份、自动更新源（updater endpoints）、bundle identifier。它们目前仍是上游遗留，属于已知待办，不是可以直接"顺手改对"的配置。
- `cli/` 里的许可、署名与 NOTICES 文件是分发义务的一部分，不因"看起来没用"而删除。

## 破坏性操作

- 不擅自 `reset --hard` / `clean -f` / `checkout --` / `rebase` / `push --force`：先用 `git status` 确认没有别人的未提交工作会被吞掉，不确定就先停下来问。
- 不删用户文件、不动真实数据目录里的既有会话来"复现问题"。要沙箱就用隔离的数据目录（内置运行时支持 `MIREAI_DATA_DIR` 覆盖）。
- 遇到障碍（锁文件、进程占用、权限拒绝）先找持有者/根因，**不把删除当作快捷清理手段**。
