# 代码与命名

## 目录归属：改动应该落在哪

| 放这里 | 条件 |
|---|---|
| `src/features/<模块>/` | 功能行为。一个模块一个领域，模块内部自己分层 |
| `src/components/base/` | 与业务无关的基础控件（按钮、输入、选择器、开关、页签、提示） |
| `src/components/application/` | 跨功能的应用级组件（聊天输入区、设置壳、头像、状态栏） |
| `src/components/foundations/` | 更底层的展示件（图标） |
| `src/lib/` | 跨切面能力：`ipc.ts`（后端调用面）、`events`、`storage`、`transport`、`zoom` |
| `src/hooks/`、`src/utils/` | 真正被两处复用的 hook 与工具 |
| `src-tauri/src/features` 对应模块 | 原生能力。**协议差异只准留在 `engine/` 适配层** |
| `packages/plugin-sdk/` | 插件公共契约。改它等于改对外 API |

**不要把引擎特判散进 UI**。能力由引擎广播（模型目录、斜杠命令、推理档位、是否支持 plan），前端只读能力位；判定引擎身份只走集中常量入口（`isBundledEngine` / `MIREAI_ENGINE_ID` 这类），不散写字符串比较。

## 命名

- **TypeScript**：变量与函数 camelCase，组件与类型 PascalCase，文件用 kebab-case。
- **组件文件与文件目录内现有风格一致**：本仓两种都在——`components/application/**` 多为 kebab（`composer-editable.tsx`），`features/chat/components/` 多为 PascalCase（`MessageTimeline.tsx`）。进到一个目录先看邻居，别在一个目录里制造第三种风格。
- **测试**：与被测文件同目录同名 + `.test.ts(x)`，纯 TS 逻辑测试也可放同目录。
- **Rust**：模块与函数 snake_case；命令加 `#[tauri::command]`；序列化对外一律 camelCase（`#[serde(rename_all = "camelCase")]`）。
- **设置字段是三态**：`Option<bool>` / `Option<u16>` 配 `#[serde(default)]`，`None` = 跟随默认、`Some(x)` = 用户明确选过。前后端都不许当普通值用，否则"没设置过"会被当成"关了"。

## 注释纪律

默认**不写**注释。只在下面三种情况写，且写的是"为什么"：

- 隐藏约束（例：`AttachmentChips` 里 store 读取必须放在 early return 之前，否则 hooks 顺序变了）
- 微妙不变量（例：某处缓存必须去缓存读取，否则会冲掉另一端刚写的值）
- 针对具体缺陷的 workaround（例：`notarytool` 不用 `--wait` 的原因）

不写"这行做什么"（好命名已经说明了），也不写"为哪个任务加的"（那属于 PR 描述，会随代码演进腐烂）。多段 docstring 与注释块同理，一行说清即可。

## 必须成对同步的镜像清单

这是本项目最容易出问题的一类改动——**不同步时不会报错，只会静默变坏**：

| 你改了这个 | 必须同时改 | 漏了会怎样 |
|---|---|---|
| `src/styles/typography.css` 里 `@theme` 的 `text-*` token 名 | `src/utils/cx.ts` 的 `TEXT_FAMILIES` / `TEXT_WEIGHTS` | tailwind-merge 把它当颜色类，与真颜色同框时**静默丢样式**，不报错 |
| `settings.rs` 的 `AppSettings` 字段 | `src/lib/ipc.ts` 的 TS 接口、设置页行、`src/features/settings/builtin-search.ts` 锚点、`zh.ts` + `en.ts` 文案 | `builtin-search.test.tsx` 双向断言锚点集合与双语存在性 → 红 |
| `packages/plugin-sdk`、扩展点、权限目录 | `pnpm plugin-skill:docs` 重生成 `src-tauri/resources/skills/.../references/sdk-api.md` | `creator-skill-docs.test.ts` 断言生成物与源码一致，过期即红；插件作者看到的说明书是错的 |
| 新增后端命令 | `#[tauri::command]` → `lib.rs` 的 `invoke_handler` → `web/dispatch.rs` 分发臂（三处） | 桌面正常，**手机端报未知命令** |
| 新增 `cli/` 测试文件 | `cli/test/vitest-suites.json` | 测试**静默不被执行**（清单是声明式的） |
| 新增 `cli/` 源文件 | `node scripts/source-inventory.mjs --write`（更新 `cli/release/public-source.json`） | 开源发布清单与源码不符，门禁红 |
| i18n 任一 key | `zh.ts` 与 `en.ts` 成对 | 界面显示 key 原文 |
| 新增/修改用户可见交互、视觉、动效时长 | `docs/ui-ux-spec.zh-CN.md` 同一改动内更新（见 [文档与界面文案](./文档与界面文案.md)） | 规范与实现漂移，下一个人按错的做 |

## 静态检查的实情

仓库**没有 ESLint / Prettier / editorconfig**，也没有格式化门禁。风格由三件事维持：TypeScript `strict`（`pnpm build` 里的 `tsc --noEmit`）、评审对照现有代码、上表那些有测试看守的约定。

因此：**不要在功能 PR 里顺手加 lint 配置或全仓格式化**——那会让每个文件 diff 变脏、掩盖真实改动。需要引入工具链时单独提一个改动说明理由与影响面。

## 其他硬约束

- **不写死与机器相关的值**：端口、绝对路径、真实租户/账号 ID 不进代码、示例与测试。
- **删除旧实现前先查调用方**：还有没有外部契约（插件、手机端、历史会话数据）。有兼容性顾虑时先消解不确定性，而不是留着死代码当保险。
- **不为猜测中的未来需求造抽象**；同一根因影响多个入口时一并处理，但语义不同的实现不强行合并。
- 避免"向后兼容垫片"式改动：改名未使用的变量、导出空类型、留 `// removed` 注释都不算清理——确定没人用就删干净。
