# 架构与数据流

前面包是 React，后面是 Rust，中间是**命令 + 事件**。真正需要理解的是：一条消息怎么从输入框走到外部 CLI，再流回屏幕。

---

## 1. 一次发送的完整链路

```
输入框 Enter
  src/components/application/ai-chat/composer-editable.tsx   （IME 与快捷键门控）
    → ChatPage / ConversationFooter 的 onSubmit
      → src/features/chat/store/messaging.ts:428  ipc.sendMessage({...})
        → src/lib/ipc.ts:1493                     invoke("send_message", {...})
          → src-tauri/src/engine/mod.rs:709       send_message → :859 send_message_inner
            → prepare_launch：解析 CLI 路径、拼参数、注入渠道 env
            → 具体适配器（claude.rs / codex.rs / kimi_acp.rs / dsh_session.rs / mcode_acp.rs …）
              启动子进程，读它的 stdout / RPC
            → src-tauri/src/engine/events.rs      把各家事件归一成同一种内部事件
          → src-tauri/src/event_sink.rs:13        事件名 "engine://event"
            :119 EventSink::with_interval(..., CHAT_FLUSH_INTERVAL) 按帧批量发
    → src/features/chat/store/engine-events.ts    落到该会话的 state
      → MessageTimeline / Markdown 渲染
```

要点：

- **一个会话只有一个发送消费者**。流式期间再发消息进队列（`MessageQueue`），不并发起第二个写者。
- **完成、中断、错误、恢复都必须收敛**。`ipc.interruptSession` 请求取消，取消不等于回滚；要等进程终态才算忙碌结束。
- **展示优化不能改原文**。流式平滑只影响显示，不许丢字、重复、乱序；中文与 emoji 边界、Markdown 结构、代码块、复制内容都在验证范围内（见 `tests/*.test.ts`）。

## 2. 引擎适配层：差异收敛在哪

`src-tauri/src/engine/` 是**唯一**允许出现引擎协议差异的地方：

- `registry.rs` 引擎清单；`resolve.rs` 找可执行文件（Windows 下会在检测时重读注册表 PATH，因为 GUI 进程继承的是启动那一刻的 PATH 快照）
- 每个引擎一到数个适配器文件：ACP 协议的（`kimi_acp.rs` `grok_acp.rs` `omp_acp.rs` `mcode_acp.rs`）、自有 JSON 流的（`claude.rs` `codex.rs` `dsh*.rs` `agy.rs` `opencode*.rs` `qoder*.rs`）、`pi_family.rs`（Pi 与 OMP 共用一族）
- `bundled.rs` + `mr_providers.rs` + `channel.rs`：内置运行时（引擎 id `mireai`，二进制 `mr`）的渠道写入与调用面
- `models/`、`provider_models.rs`、`provider_files.rs`：模型目录与供应商配置文件
- `job.rs`（Windows Job Object，孤儿孙进程随应用死掉）、`images.rs`（粘贴/附件图片落盘）、`plan_review.rs`（计划审批）

**引擎能力是广播出来的，不是 GUI 猜的**：模型目录、斜杠命令、推理档位、是否支持 plan 权限，都从引擎上报（`available_commands_update` 等）转成前端能力位。前端只读能力位，不写 `if (engine === "xxx")`。唯一的例外是集中定义的引擎常量入口（`isBundledEngine` / `MIREAI_ENGINE_ID` 这一处），判定都走它。

新增一个引擎的最小动作：加适配器 → 进 `registry.rs` → 在 `resolve.rs` 能被找到 → 前端 `src/features/settings/providers.ts` 与图标品牌表登记 → 补 `cargo test` 里它的协议解析用例。

## 3. 命令与事件面

**加一个后端命令必须动三处**，缺一处就是"桌面正常、手机报错"：

1. `#[tauri::command] pub async fn xxx(...)`
2. `src-tauri/src/lib.rs` 的 `invoke_handler` 注册
3. `src-tauri/src/web/dispatch.rs` 的匹配臂（`parse_args` + `ser(...)`）——这是手机浏览器经 web 桥调用同一条命令的入口

主要事件名（`src-tauri/src/event_sink.rs`）：

| 事件 | 用途 |
|---|---|
| `engine://event` | 会话流式事件（按 `CHAT_FLUSH_INTERVAL` 批量） |
| `sessions://changed` | 会话列表需要重扫 |
| `settings://changed` | 设置变了；走 `EventSink` 时**同时**送达 webview 和所有连上的浏览器 |
| `plugin-agent://event` / `mission-agent://event` | 插件、任务工作台的代理会话 |
| `web://relay` | 中转连接状态变化 |
| `scan://progress`、`plugin://install-progress`、`cli://update-progress` | 长任务进度 |

广播设置变更统一用 `settings.rs` 的 `announce_settings()`，别自己 `app.emit`——直接 emit 只到桌面，手机端会看到旧值。

## 4. 存储与持久化

| 数据 | 位置 | 注意 |
|---|---|---|
| 应用设置 | `settings.rs` 序列化到应用数据目录的 `settings.json`（字段 camelCase） | 开关类字段是 `Option<bool>` **三态**：`None` = 跟随默认，`Some(false)` = 用户明确关。前后端都不能当普通 bool 用，否则"没设置"和"关了"会互相覆盖 |
| 未知旧字段 | `AppSettings` 有 `#[serde(flatten)]` 的附加字段表，非已知键会原样往返 | 删字段时必须在写盘前显式丢弃老键，否则老用户文件里那个键会被永久回写 |
| 会话与索引 | `db.rs` 打开的 SQLite | 会话正文的**权威在各 CLI 自己的会话文件**里；本应用只做发现（`history/discovery.rs`）、扫描入库、搜索、标题侧表（`session_auto_titles`） |
| 内置运行时数据 | `~/.mireai`（渠道配置、会话、缓存；`MIREAI_DATA_DIR` 可覆盖） | 与官方 MiniMax Code 的 `~/.minimax` **刻意隔离**，两个引擎各有目录 |
| 前端镜像 | `localStorage`，键前缀 `ccgui-next.*` | 首帧前由 `bootstrap.tsx` 读镜像应用（主题、字体、缩放），避免闪一下 |
| 长期记忆文件 | `<数据目录>/memory/`（全局 + 按项目分组） | 设置→记忆页只负责开关与"在文件管理器里查看"；真正的读写在内置 CLI 侧 |

**API key 的红线**：渠道密钥存在用户本地配置文件里（明文），**只允许通过子进程环境变量传给对应 CLI**；不得进命令行参数、日志、崩溃上报、截图说明或提交记录。日志要留错误上下文，但不输出凭据、完整用户对话或其他敏感数据。

## 5. 远程访问（web 桥 + 中转）

- `web.rs`：局域网 HTTP + token 认证 WebSocket，把命令面与事件面桥给浏览器；`web/dispatch.rs` 是它的命令分发。
- `relay.rs`：拨出到 Cloudflare Worker（`deploy/worker/`），让外网设备连回来。
- **中转开关是会话态**，只有"无人值守"这一半持久（重启后才自动拨号）；`web_relay_stop` 会先清标记再断，一次点击表达"别自己回来"。
- 手机能管的命令必须在 `dispatch.rs` 有臂；拿不到 OS 能力的（例如剪贴板文件路径）在该层显式回空，而不是让前端猜。

## 6. 插件体系

- 公共契约在 `packages/plugin-sdk`（`manifest` / `registry` / `context` / `permissions` / `contract-check` / `version`），共享组件在 `packages/plugin-ui`。
- 宿主侧：`src-tauri/src/plugins/`（manifest 审查、文件系统、市场、状态、存储）+ `plugin_host.rs` + `plugin_caps.rs`（权限）。
- 界面扩展点通过同一套注册表接入——设置页就是这条链路的"自用面"（内置页与插件页走同一个 `settingsRegistry`）。
- **改了 SDK / 扩展点 / 权限目录，必须在同一个改动里跑 `pnpm plugin-skill:docs`** 重新生成内置插件开发 skill 文档：那是插件作者和 AI 看到的说明书，`creator-skill-docs.test.ts` 会断言生成物与源码一致，过期即红。

---

## 7. 前端状态与渲染的性能口径

- 未变消息的引用要稳定，历史列表、已完成工具行、代码块不能每帧重算。
- 缓存必须有边界，考虑插件改节点时的隔离。
- 定时器、帧回调、订阅、子进程都要有清理路径：卸载、后台、取消、旧任务晚到的更新，四种情况都要想。
- 性能结论必须写清测量对象与条件，区分"上游到达间隔 / IPC 等待 / 解析成本 / 页面显示延迟"。没测过不许说提升了。
